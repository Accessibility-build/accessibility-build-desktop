# Mac App Store

The App Store build is the `AccessibilityBuildAppStore` target: the same app
and bundle ID (`build.accessibility.desktop`) as the website download, with
three differences, all required by App Review:

| | Website build | App Store build |
|---|---|---|
| Updates | Sparkle, from `accessibility.build/desktop/appcast.xml` | The App Store (guideline 2.4.5: apps may not update themselves) |
| Network entitlement | Yes, for the update check | None: the app makes no network requests |
| Temporary-exception entitlements | Sparkle's two installer services | None (unjustified exceptions are rejected) |
| Signing | Developer ID, notarized | Apple Distribution, via Xcode automatic signing |

Code differs only under the `APP_STORE` compilation condition
(`Updater.swift`, the Updates section in Settings, the menu's Check for
Updates item, and the network sentence in `AppLinks`).

## Review checklist (what App Review looks for)

| Guideline | Status |
|---|---|
| 2.1 Completeness: the app works for the reviewer | Welcome window on first launch and on every reopen; Check Colors works without any permission. **Still needs a live test on a real screen.** |
| 2.3 Accurate metadata and screenshots | Screenshots below are the real interface, generated by `APP_STORE=1 scripts/snapshots.sh` (the `app-store` folder) |
| 2.4.5 Mac rules: sandbox, no self-updating, no login items without consent | Sandboxed; no Sparkle; Open at Login is off until the user turns it on |
| 2.5.1 Public APIs only | ScreenCaptureKit, CoreGraphics, AppKit, SwiftUI; no private API |
| 4.2 Minimum functionality | Picker, lens, captures, session log |
| 5.1.1 Privacy policy URL and in-app link | `https://accessibility.build/desktop/privacy`, linked from Settings > Privacy and the About window |
| 5.1.1 Data use explained before permission | Screen Recording is explained in the app before macOS asks |
| Export compliance | `ITSAppUsesNonExemptEncryption = NO` in the App Store Info.plist |
| Privacy manifest | `PrivacyInfo.xcprivacy` declares the one required-reason API (UserDefaults, CA92.1) |

Check accessibility anywhere on your screen, in any app, from the menu bar.

CONTRAST PICKER
Freeze the screen and pick the text and background colors with a magnified loupe, by mouse or entirely by keyboard. COLOR-VISION LENS
A floating lens that shows whatever is beneath it as people with protanopia, deuteranopia, tritanopia or achromatopsia may see it. Adjust severity, add blur or contrast loss for low vision, and split the view to compare.

## Notes for App Review

Paste into App Review Information > Notes:

> Accessibility Build is a menu-bar app with no Dock icon. On first launch a
> Welcome window explains where its icon is (top right of the menu bar,
> next to the clock). Reopening the app from Finder or Launchpad shows the
> Welcome window again.
>
> Screen Recording permission is needed because the tools read pixel colors
> from other apps' windows: the contrast picker freezes the screen and reads
> the exact sRGB value of the pixels the user picks, the color-vision lens
> shows the area under it through a color-blindness filter, and captures
> save a region the user selects. Everything is processed on the Mac. The
> app has no network entitlement and sends nothing anywhere.
>
> To try it:
> 1. Choose "Allow Screen Recording…" in the Welcome window, turn on
>    Accessibility Build in System Settings, then choose Quit and Reopen.
> 2. Click the menu bar icon and choose Pick Contrast… (or press
>    Control-Option-Command-C). Click any text, then its background. The
>    results window opens with WCAG 2.2 verdicts.
> 3. Choose Color-Vision Lens (Control-Option-Command-L) and move it over
>    anything colorful.
> 4. Without the permission, choose Check Colors… and type two hex colors,
>    for example #767676 and #FFFFFF.
>
> No account or sign-in is needed.

## Submitting

What needs you (Apple account access):

1. **App Store Connect, My Apps, +, New App:** platform macOS, name above,
   primary language English (U.S.), bundle ID `build.accessibility.desktop`
   (if it is not listed yet, `scripts/release-appstore.sh` registers it
   through Xcode's automatic signing on the first run), SKU above.
2. Approve the first run of `scripts/release-appstore.sh upload`: it lets
   Xcode register this Mac and the bundle ID and create the App Store
   profile in your developer account, archives a universal Release build of
   the App Store target, signs it with Apple Distribution and the 3rd Party
   Mac Developer Installer certificate, and uploads it.
3. Fill in the listing above, upload the five screenshots, pick the
   uploaded build, answer App Privacy with Data Not Collected, and submit.

`scripts/release-appstore.sh export` does everything except the upload and
leaves the signed `.pkg` in `build/appstore/export` for inspection.

Each upload needs a higher `CURRENT_PROJECT_VERSION` in `project.yml`; the
website and App Store builds share the version and build numbers.
